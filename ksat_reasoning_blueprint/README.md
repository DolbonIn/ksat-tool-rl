# 수능·모의고사 추론 학습 데이터셋 제작 명세
기준일: 2026-11-18 · 대상: 국어·수학·영어, 우선 3~4B 온디바이스 학생 모델

## 0. 이 패키지의 범위와 현재 상태
이 패키지는 공개 추론 데이터셋 조사, 제작 명세, 스키마, 생성·검증 프롬프트, 오프라인 검사·내보내기 코드입니다. 전체 기출 원문을 수집하거나 새 대규모 풀이를 생성하거나 모델을 학습한 결과물이 아닙니다.

이전 자료에는 예상 문항 자리 5,145개(기본 35회)와 별첨 882개가 표시되어 있지만, 이것은 실제 확보한 원문 수가 아닙니다. 기존 JSONL은 28개 해설 초안이며 question_text=null, human_review=false, training_ready=false입니다. 기존 해설을 `legacy/problems_28.jsonl`과 `legacy/traces_28.jsonl`로 분리해 보존했으며 전부 quarantine, intended_split=test로 두었습니다. 실제 시행연도 2025년 문항이기 때문입니다.

새 학습 준비 완료 레코드: 0. 기존 원문·해설의 검수 상태를 개선한 것으로 표시하지 않았습니다. 설명 문체를 정리하는 것과 정답·논증을 검증하는 것은 별개의 작업입니다.

## 1. 공개 레시피 비교
다음은 공개 카드·논문에 보고된 값입니다. 독립 재계수나 KSAT 학습 재현 결과가 아닙니다. 최신 전체 모델의 절대 순위를 의미하지도 않습니다.

| 자료 | 공개 규모 | 구조와 활용 포인트 |
|---|---:|---|
| Nemotron-Math-Proofs-v3-SFT [S01,S03] | 고유 문제 15,818 / 예제 414,890 | proof·refinement·verification·meta_verification, messages 및 reasoning_content |
| Nemotron-Math-Proofs-v3-RL [S02] | 고유 프롬프트 9,597 | 완성 풀이 없이 문제를 저장하고 정책 응답·보상은 학습 중 생성 |
| Nemotron-SFT-Math-v3 [S04] | 예제 3,638,783 | 도구 없는 CoT와 Python TIR, messages·expected_answer·tool_usage |
| OpenMathReasoning [S05] | 풀이가 연결된 고유 문제 약 306K | CoT 3.2M, TIR 1.7M, GenSelect 566K; 추가 prompt-only 193K |
| OpenThoughts3-1.2M [S06,S07] | 학습 쌍 1.2M | QwQ-32B 생성, conversations 형식; 수학 850K·코드 250K·과학 100K |
| OpenR1-Math-220k [S08] | 권장 default 약 94K 문제 행 | 후보 리스트, 종료 여부, Math-Verify 등 검증 결과 |
| s1K [S09,S10] | 1,000 예제 | 소량 고품질 선정 및 추론 예산 실험의 참고 사례 |

보고해야 하는 단위는 고유 문제 수, 고유 지문/문제군 수, 생성 후보 수, 합격 학습 예제 수, 입력/출력 토큰 수입니다. 여러 풀이를 만든다고 고유 문제가 증가하지 않습니다. 다운로드 수·뷰어 추정 행 수를 학습 규모로 사용하지 않습니다.

OpenThoughts3의 실험에서는 더 높은 벤치마크 성능의 모델이 반드시 더 좋은 teacher가 아니었으며, 검증·답변 필터링이 유의한 개선을 보이지 않았습니다. 따라서 아래 검증 단계는 모든 과제에서 입증된 성능 증가 공식이 아니라, 정답과 근거가 중요한 교육용 제품의 품질 통제와 실험 설계입니다. [S06]

## 2. 전체 아키텍처
원본 자산 → 문항/지문 정규화 → 중복·계보 연결 및 split 고정 → 정답 비공개 후보 생성 → 정답/풀이 별도 검증 → 오류 수정 → 재검증 → 길이별 버전 → SFT/선호/RL export → 고정 평가 → 배포 양자화 평가.

보관용 정본과 학습기용 파일을 분리합니다.
- problems: 문제당 1행. 원문·선지·지문·자산·정답·출처·권리·split.
- traces: 후보/작업당 1행. problem_id로 연결. teacher·생성 설정·풀이·검증 보고서.
- training exports: 필요한 입력과 정답 목표만 직렬화. provenance와 gold는 입력에 섞지 않습니다.
- assets: 이미지·음원 원본과 SHA-256. 학습 데이터와 별도 저장하되 버전 관리합니다.
- manifests: 원본 hash, 코드 commit, 모델/tokenizer revision, prompt hash, 검증기 버전, 실행 ID.

공개 모델이 제공한 reasoning trace, 작성된 교육용 해설, 검증기 피드백을 구분합니다. 작성된 풀이를 모델의 실제 비공개 내부 사고 기록이라고 표시하지 않습니다.

## 3. 분할과 누수 방지
다음은 이 프로젝트의 제안안이며 문항 전수 확보 후 조정합니다.
| 실제 시행연도 | 역할 | 중복 제거 전 예상 자리 |
|---|---|---:|
| 2021~2023 | train | 3,087 |
| 2024 | validation | 1,029 |
| 2025 | test | 1,029 |

공통 지문, 동일 원문을 이용한 다른 문항, 홀수/짝수형, 번역, 숫자 변형, 이미지/텍스트 버전, 설명/압축/수정 예제는 연결된 family 전체를 같은 split에 둡니다. 연도를 넘나드는 중복이 있으면 시험지 연도만으로 분할하지 말고 연결 요소 전체를 재배치하거나 격리합니다. 현재 예상 개수는 이 작업 이후 줄거나 달라질 수 있습니다.

원본 전체를 archive에 보관하는 것과 전부 학습에 사용하는 것은 다릅니다. 평가용 지문의 해설·오답 분석·재작성까지 train에 넣으면 안 됩니다. 공개 기출에 대한 기반 모델의 사전학습 오염은 이 분할로 제거되지 않으므로, 별도의 비공개 자작 검수 문제와 시간적으로 새로운 봉인 평가도 필요합니다. HRM8K 같은 공개 평가셋도 학습과 평가에 중복 사용하지 않습니다. [S16]

## 4. 스키마와 학습 형식
`schemas/problem.schema.json`, `schemas/trace.schema.json`은 미완료 자료를 표현할 수 있습니다. 스키마를 통과했다는 사실은 학습 승인과 다릅니다. 승인 보고서와 권리 근거, 정답/풀이 검사, split 검사까지 별도로 통과해야 합니다.

중요 필드:
- problem_id: 기출 문항의 안정적 식별자. academic_year와 administration_year를 구분합니다.
- family_id, parent_problem_ids: 동일 지문·원문 및 변형 계보. 그룹 미확정이면 격리.
- input.passages: text와 안정적인 ID. 근거 오프셋의 기준이 되는 문자열을 변경하지 않습니다.
- input.choices: 표시 순번과 선택지 내용을 분리. 선지 순서 변형 시 gold.choice_id도 갱신.
- gold: 검증기 전용 정답. 초기 풀이 생성의 입력에는 포함하지 않습니다.
- solution.rationale / final / steps / evidence: 검증 가능한 풀이와 최종 답, 구조화된 단계, 근거 위치.
- generation.gold_visible: 정답을 보고 생성·수정했는지. unknown을 false로 대체하지 않습니다.
- generation.finish_reason: length 또는 미확인은 합격 처리하지 않습니다.
- checks: answer와 rationale을 별도 판정하고 보고서 참조를 저장.
- tokens: 대상 tokenizer로 실제 센 입력·풀이·최종 답 길이. 미계수는 null이지 0이 아닙니다.

SFT는 `prompt`+`completion` 또는 `messages`를 사용할 수 있습니다. 선호학습은 `prompt/chosen/rejected`, RL은 `prompt`와 검증용 gold를 보관합니다. TRL의 공식 형식과 맞추되 target template를 실제로 확인해야 합니다. [S12,S13,S14]

`reasoning_content`를 JSON에 넣었다고 자동으로 학습되지 않습니다. 해당 필드를 읽지 않는 chat template는 조용히 버릴 수 있습니다. 반대로 think 태그를 수동 삽입하고 템플릿이 다시 넣으면 중복됩니다.
학습 전 필수 테스트:
1. tokenizer.apply_chat_template 결과에 풀이와 정답이 모두 존재하는지 확인.
2. system/user/padding loss mask와 assistant 목표 구간을 검사.
3. truncation 후 final이 사라지지 않는지 확인.
4. 한 배치를 decode하여 특수 토큰·eos·thinking 경계와 시작 prefix를 확인.
5. packing 사용 시 독립 예제의 경계 처리를 검사.
assistant_only_loss는 적절한 generation mask를 반환하는 템플릿이 필요합니다. 문서 옵션을 켰다는 이유만으로 검사를 생략하지 않습니다. [S12]

## 5. 과목별 검증
수학:
정답표 대조, 유리수/정수 정확 비교, 기호 동치, 정의역, 부호, 필요충분성, 경우 누락, 존재/유일성 검사를 분리합니다. CAS 또는 수치 대입은 보조 도구이며 수치 검사가 증명을 대체하지 않습니다. 복잡한 기하·그래프는 원본 이미지와 함께 검수합니다.

국어:
문단·문장 ID와 근거 span을 저장하고 선지별로 지지/모순/근거부족을 판정합니다. '일부→전부', '가능→필연', 인과 역전, 주체·시점 변경을 별도 오류 유형으로 기록합니다. 문학 해석을 외부 상식으로 단정하지 않고 지문·보기의 범위를 보존합니다.

영어:
원문 영어를 입력에 유지하고 한국어 해설을 만들 수 있습니다. 빈칸·순서·삽입은 연결 관계와 대조·지시어 근거를 기록합니다. 어법은 문장 구조와 수정 후 문법을 따로 확인합니다. 번역이 원문의 양태·부정·범위 정보를 바꾸지 않았는지 검사합니다.

듣기:
음원 기반과 정답 스크립트 기반은 서로 다른 트랙입니다. 텍스트 모델의 transcript-only 점수를 audio 문제 이해 성능이라고 보고하지 않습니다. 필요한 음원이 없으면 incomplete로 보관합니다.

모든 과목:
공식 정답과 모델 다수결이 다르면 정답표·정오표·파싱을 검토합니다. teacher 투표로 공식 정답을 덮어쓰지 않습니다. 정답은 맞아도 논증이 틀리면 교육용 gold에 포함하지 않습니다.

## 6. 후보 생성·검증·수정
첫 pilot은 train에서 과목/유형/난도별 고유 문제 1,000개를 선정합니다. 문제당 4개, 어려운 것은 최대 8개까지 생성해 teacher 간 비교를 합니다. 2개 독립 teacher를 권장하지만 같은 모델 다른 seed가 독립 오류를 보장하지는 않습니다.

teacher 선정은 모델 순위가 아니라 동일 예산에서 학생 모델에 미치는 효과로 판단합니다. A만 사용, B만 사용, 혼합의 세 실험을 비교합니다. 처음부터 API 모델이나 공개 모델의 특정 이름을 최적값으로 고정하지 않습니다.

초기 solver에는 gold와 기존 해설을 주지 않습니다. 검증기는 별도 호출에서 gold를 볼 수 있습니다. answer check와 rationale check를 분리합니다. 서로 충돌하는 판정은 사람이 확인합니다. 정답을 알려 준 repair는 provenance를 남기고 repair 과제로 보존합니다.

최대 2회 수정 후에도 실패한 사례는 삭제하지 않고 failure pool로 보관합니다. 파싱 오류, 입력 누락, 해답 생성 실패, 검증 불일치, 저작권 상태, 중복 등 탈락 사유를 분리해 집계합니다. 실패 사례는 모델 난도 추정에도 활용하되 틀린 풀이를 정답 SFT로 쓰지 않습니다.

전체 golden seed의 원문·정답을 사람이 확인하고, 모든 고난도/분쟁/새 유형을 우선 검수합니다. 자동검증 기반 silver를 운영한다면 두 검증기의 독립성, 표본 감사 방식, 승인 기준을 별도 정책으로 정의합니다. 첨부 exporter는 더 보수적인 human-reviewed gold-only입니다.

## 7. 분량: 시작점과 확장 계획
아래는 실험 시작을 위한 제안이며 논문이 확정한 최적 분량이 아닙니다.

Pilot: 고유 train 문제 1,000개 → 후보 4,000~8,000개 → 합격 SFT 목표 2,000~4,000개.
V1: 신규 자작·검수 문제와 이용 가능한 외부 문제를 포함해 도메인 train 고유 문제 15,000~25,000개를 목표로 하되, 원문 확보·권리·검증이 선행됩니다.

V1 SFT 80,000개 구성 예:
| 유형 | 예제 수 |
|---|---:|
| 문제 → 검증된 풀이 | 40,000 |
| 문제+후보 → 오류 검증 | 12,000 |
| 문제+오류+피드백 → 수정 | 12,000 |
| 동일 조건에서 더 짧고 정확한 풀이/압축 과제 | 8,000 |
| 일반 한국어·지시 수행 등 replay | 8,000 |
| 합계 | 80,000 |

추가 DPO 5,000~15,000쌍은 선택 사항이며 SFT 80,000에 포함하지 않습니다.
RL 문제 풀 5,000~10,000개도 별도이며 동일 문제에 대한 온라인 rollout 수와 구분합니다.
기존 3천여 train 기출을 20번씩 복제해 6만개의 독립 문제라고 표시하면 안 됩니다.
합성 변형은 변형 후 정답 유일성·교육과정 적합성·지문 의미·선지 정합성을 다시 검수합니다.
숫자 치환, 선지 재배열, 문단 이동은 모두 안전한 변형이 아니므로 연산별 전제와 정답 갱신 로직이 필요합니다.

권장 시작 출력 길이(대상 tokenizer 기준):
- 쉬운 풀이: 256~1,024 tokens
- 표준 풀이: 1,024~2,048 tokens
- 어려운 풀이: 2,048~4,096 tokens
- 예외: 최대 8,192, 필요성 검토
범위 하한은 강제 최소 길이가 아닙니다. 간단한 문제는 더 짧아도 됩니다.
초기 context cap 16,384에는 입력·출력·템플릿 토큰을 모두 포함합니다. 긴 지문이나 멀티모달 토큰 때문에 넘치면 지원되는 긴 문맥 경로로 보내거나 격리하지, 문제/정답을 잘라내지 않습니다.

상세 교육용 해설은 접근 이유·개념·선지별 분석·검산을 풍부하게 담되, 온디바이스 풀이 길이와 별도 모드로 둡니다. 같은 긴 설명을 rationale와 final에 중복 복사하지 않습니다.

## 8. 토큰·비용 계산
가정 예: 80,000 예제, 평균 입력 1,500 + 출력 2,000 tokens.
전체 노출량 280,000,000 tokens/epoch, 출력 목표 160,000,000 tokens/epoch입니다.
이 값은 실제 데이터 통계가 아니라 산술 예시입니다. prompt를 loss에서 마스킹해도 forward 비용은 없어지지 않습니다.
1~2 epoch는 초기 실험 범위일 뿐이며 validation으로 선택합니다.

생성 측 가정 예: 고유 문제 20,000 × 후보 8 × 평균 출력 4,000 = 640,000,000 출력 tokens.
이외에 입력, 검증기, 수정, 번역, 오류 재시도가 추가됩니다.
API 비용 = Σ[(입력 토큰×입력 단가)+(출력 토큰×출력 단가)]/1,000,000.
실제 사용 모델·시점의 단가와 pilot 합격률을 측정한 뒤 예산을 정합니다.
공개 데이터의 teacher-token 수는 target tokenizer의 길이와 같지 않으므로 재계수합니다.

## 9. 학습 및 평가 실험
권장 순서: 원본 학생 baseline → pilot SFT → V1 SFT → 선택적 선호/온라인 RL.
선호학습과 GRPO는 모두 반드시 해야 하는 단계가 아닙니다.

GRPO는 모델이 문제당 여러 답을 생성하고 외부 채점기가 보상합니다. 정답표를 policy prompt에 넣지 않습니다. [S14]
객관식은 정답 번호만 맞힐 수도 있으므로 답 정확도와 근거 타당성을 별도로 모니터링합니다.
처음부터 LLM judge 점수를 절대 진실로 쓰지 않습니다. 형식 보상이 오답 보상을 압도하지 않게 하고, 긴 출력 자체에 보상을 주지 않습니다.
모든 후보가 맞거나 모두 틀리는 그룹의 비율과 보상 분산을 관측합니다. 데이터 난도·샘플링을 조정하되 쉬운 문제를 무조건 제거하지는 않습니다.
도구 없는 배포가 목표면 no-tool SFT/RL을 기본으로 하고 Python TIR은 별도 트랙으로 관리합니다. 존재하지 않는 tool 응답을 모델이 흉내내게 만들지 않습니다.

평가 표 필수 열:
모델/체크포인트, 데이터 hash, 학습 예제·고유 문제·토큰 수, 과목/유형, pass@1,
고정 출력 예산, 입력 방식(text/image/audio), 도구 허용 여부,
풀이 근거 오류율, truncation 비율, 평균/p95 출력 토큰, 실제 장치 지연·메모리, 양자화 설정.
best-of-N/majority와 1회 응답을 같은 점수로 비교하지 않습니다.

최소 ablation:
1. answer-only vs structured rationale
2. 1개 풀이/문제 vs 다중 풀이 (고유 문제 수 통제)
3. 영어 풀이 vs 한국어 풀이 (한국어 final 고정)
4. solve-only vs solve+verify+repair (총 토큰 예산도 통제)
5. 짧은 풀이 vs 긴 풀이 (pass@1와 지연 함께)
6. 원정밀도 vs 실제 배포 Q4 등 양자화
validation으로 recipe를 정한 뒤 test는 최종 확인에 사용하고 계속 튜닝하지 않습니다.
검증셋 반복 사용으로 인한 적응적 과적합도 기록합니다.

## 10. 공개 도구에서 가져올 부분
NeMo-Skills의 공개 파이프라인은 질문 수집/처리, 후보 생성, 정답 판단, 필터링, export를 재현하는 참고 구현입니다. [S11]
그러나 KSAT에 적용할 때 MCQ 제거, proof 제외, 공식 정답을 majority로 변경하는 부분을 그대로 가져오지 않습니다.
문제 수집기와 passage/choice/image/audio parser, 공식 정답 연결기, 한국어 근거 검증기는 별도 구현해야 합니다.
코드와 데이터·모델 revision을 고정한 pilot부터 수행합니다.

Nemotron multilingual은 번역 기반 자료이며 reasoning을 영어로 유지하고, 한국어 subset도 제공하지 않습니다. 다국어라고 해서 국어 독해 데이터로 대체하지 않습니다. [S15]

## 11. 실행 가능한 부분과 미구현 부분
포함:
- problem/trace JSON Schema
- 생성·검증·수정·압축 프롬프트
- SFT/native reasoning/선호/RL의 자작 형식 예제
- 기존 28개 해설을 상태를 보존한 채 이관한 problem/trace 파일
- 텍스트 solve SFT 및 객관식/유리수 RL의 엄격한 검사·export
- 12개 단위 테스트와 기존 28개 차단 감사 결과

미구현:
원문 수집, PDF/이미지/음원 파싱, 의미·시각 중복 탐지, teacher API 호출,
수학/언어 자동 검증기, 사람 검수 UI, 실제 권리 판단,
verify/repair/preference 전용 export, 멀티모달 export,
모델별 tokenizer round-trip/loss mask 검증, 학습·평가·장치 벤치마크.
코드는 보고서 참조의 존재를 검사할 뿐 참조의 진실성을 증명하지 않습니다.

## 12. 실행
Python 3.10 이상을 사용합니다.

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/audit_and_export.py \
  --problems legacy/problems_28.jsonl \
  --traces legacy/traces_28.jsonl \
  --out reports/legacy_audit
```

예상 결과는 problems=28, traces=28, accepted_sft=0, accepted_rl_prompts=0입니다.
이는 실패가 아니라 미완료/평가용 자료의 잘못된 학습 편입을 막는 결과입니다.
`--style think_tags` 또는 `--style native_fields`는 모델 프로토콜 확인 후 선택합니다.
기본은 plain이며, 어떤 mode도 대상 모델의 thinking 능력 활성화를 보장하지 않습니다.

외부 데이터 라이선스와 원문 권리, teacher 사용 조건은 각 데이터 출처별로 확인하고 evidence_ref에 기록합니다. 이 문서는 법률적 허용 여부를 판정하지 않습니다.
공개 데이터·문헌 링크는 sources.md와 sources.json에 있습니다.
